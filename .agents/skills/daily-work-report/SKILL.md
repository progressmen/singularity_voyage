# 今日日报

## 适用场景

- 用户要求根据 Git 提交生成今天的日报，并提交到万模工作台。
- 用户只说「写日报」「填日报」「今日日报」「提交工作记录」时，按本 skill 的默认参数直接执行。

不适用于：周报/月报、跨天汇总、替他人写日报、没有 Git 提交依据的主观总结。

## 默认参数

| 项 | 默认值 | 说明 |
|---|---|---|
| 提交人 | `wangzhaoqi` | 用户指定时替换 |
| 日期 | 今天（本机本地日期） | 用 `date +%F` 取，不要凭记忆写 |
| 后端仓库 | `/Users/zhaoqi/project/company_project/invest-agent/invest-agent-backend` | |
| dsh 仓库 | `/Users/zhaoqi/project/company_project/invest-agent-dsh` | |
| 站点 | `https://wanagent.wanmol.com/workbench` | |
| 浏览器 | Microsoft Edge | 必须用用户已登录的窗口 |
| 临时文件 | `.dsh/tmp/daily-report-<日期>.txt` | 工作区内，沙箱可写 |

用户在对话中给出的提交人、日期、仓库、站点优先于默认值。

## 执行流程

### 1. 采集提交（一次 shell 调用）

两个仓库分开采集，但只发一次命令。以下命令在项目根目录 `/Users/zhaoqi/project/singularity_voyage` 下执行：

```sh
node .agents/skills/daily-work-report/scripts/daily-report.mjs commits \
  --author wangzhaoqi --date "$(date +%F)" --files \
  /Users/zhaoqi/project/company_project/invest-agent/invest-agent-backend \
  /Users/zhaoqi/project/company_project/invest-agent-dsh
```

规则：

- **只用 shell 工具执行命令**。不要打开 iTerm/Terminal 应用去敲命令、再靠截图读输出——这是历史上最慢的路径。
- 输出已排除 merge 提交；merge 不产出日报条目。
- 提交信息笼统（`fix`、`update`、`优化` 等）时，说明提交少、需要拆分，见下一条。
- 当天提交不足 6 条时，加 `--hunks` 再跑一次，拿到函数级改动点用于拆分条目；**不要逐条 `git show` 读完整 diff**。
- 输出「（日期 无 提交人 的提交）」表示该仓库当天没有记录：跳过并如实说明，不要用其它日期的提交补齐。
- 只以提交与改动文件为事实来源，不按仓库名、目录结构或印象推测工作内容。
- 当天提交不足 6 条时，可运行 `git status --short` 与 `git diff --stat` 查看未提交改动；**必须经用户确认**后才能计入，并标注为「未提交」。

### 2. 生成条目

先按仓库各出一组草稿，再合并。必须遵守：

1. **一条一件事**：按「模块 / 功能 / 接口 / 修复 / 重构 / 脚本 / 文档」拆到一个 commit 内的多个改动点，而不是一个 commit 一条。
2. **相似合并**：同一模块的同向改动、同一功能的多次修补，合并为一条。
3. **每条不超过 30 字**（含标点），不加句号，不加「今天」「已完成」之类前缀。
4. **目标不少于 6 条**：素材不足 6 条时，按实际可得条数输出，并在末尾单独一行写「素材不足：实际 N 条」；禁止编造，也禁止把一条拆成没有信息量的碎句来凑数。
5. **动词开头**，写清「做了什么 + 对象」，例如「新增对外开放接口用于创建招商项目」。
6. **跨仓库去重**：两个仓库改同一件事时只保留一条。

写法对照：

| 差 | 好 |
|---|---|
| 改了一些代码 | 重构文件路径候选生成逻辑并补充注释 |
| fix bug | 修复 file_paths 传完整链接时报错 |
| 优化相关逻辑 | 文件路径自动关联最近研判报告 |

### 3. 合并、编号、校验

- 输出为一份**纯文本数字序号列表**，编号从 1 连续递增；不加标题、分组小标题、Markdown 符号（`*`、`#`、`-`）与结尾总结。
- 顺序：后端在前、dsh 在后；同一仓库内按重要性排序。
- 用 shell heredoc（或 `write` 工具）写入 `.dsh/tmp/daily-report-<日期>.txt`，再校验：

```sh
mkdir -p .dsh/tmp && cat > .dsh/tmp/daily-report-$(date +%F).txt <<'EOF'
1. ...
EOF
node .agents/skills/daily-work-report/scripts/daily-report.mjs check \
  --min 6 --max-chars 30 .dsh/tmp/daily-report-$(date +%F).txt
```

校验不通过就按提示修改，直到出现「✓ 校验通过」。字数超限时优先删修饰词，保留「对象 + 动作」。

当天素材确实不足 6 条时，把 `--min` 改为实际条数再校验，并在末尾保留「素材不足：实际 N 条」那一行；不要为了通过校验而编造条目。

### 4. 在 Edge 中填写并提交

使用桌面工具操作 Edge，禁止用终端 `open -a` / `osascript` / `cliclick`。快照有效期只有几十秒，点击前若已过期或页面有弹窗，先重新 `screen_observe`。

**点击定位总原则**：先 `computer_aim` 拿一张**包含虚拟光标的真实屏幕局部图**，确认光标就在目标控件上再点；不准就按图内偏移换 `screen_x/screen_y` 重新校准，最后用 `computer_click(screen_x=, screen_y=)` 点击。不要用整窗截图目测坐标，也不要盲目复用上一次的坐标。

1. **先找可操作的窗口**：`app_list` 看 Edge 是否在运行；`screen_observe(window="工作台")`。
   - 结果可能带「窗口匹配 N 个，已选当前桌面的/离屏的 window_id=…」。**只操作标注（当前桌面）的那个**，并把它返回的 `window_id` 记住，后续观察/点击都显式传 `window_id`。
   - 如果只匹配到「不在当前桌面」的窗口（常见于外接屏的另一个 Space），**不要在该窗口里输入或点击**：在当前桌面的 Edge 窗口新开标签页（`cmd+t` 或点 +），`cmd+l` 打开站点，再观察新窗口的 `window_id` 继续。
2. 看 `显示器:` 与「⚠ 该窗口不在当前 Space」两行，确认窗口可接收输入。`computer_key` / `computer_type` 返回「按键被拒绝 / 输入被拒绝：目标窗口不在当前桌面或无法前置」时，就是窗口不可交互：换当前桌面的窗口，不要重试同一动作。
3. 切文本模式：`screen_observe(window=<window_id>, query="文本模式")`，命中就 `computer_click(element=编号)`；已经是文本模式则跳过。
4. **用 `computer_aim` 校准光标，再点击**：
   - 先 `computer_aim(element=编号)` 或 `computer_aim(x=, y=)`：它会把光标移到目标，并返回一张真实屏幕局部图（含紫色虚拟光标）、光标屏幕坐标与图内位置。
   - **看光标是否落在目标控件上**。没落在上面时，按图内偏移 Δ（图片像素）换算：`新屏幕点 = 当前屏幕点 + Δ / 图片缩放比`，再 `computer_aim(screen_x=新x, screen_y=新y)`；可以连续校准几次，直到光标压在按钮中心。
   - 如果图里显示的根本不是工作台（而是别的窗口/桌面），说明该窗口不在当前 Space，坐标点击会点到别处：按第 1、2 步换到当前桌面的窗口。
   - 对准后点击：`computer_click(screen_x=光标屏幕x, screen_y=光标屏幕y)`；有元素编号也可以直接 `computer_click(element=编号)`。
5. 定位输入区：`screen_observe(window=<window_id>, query="当日工作记录")`，先点元素聚焦；AX 为空就按第 4 步用 `computer_aim` 校准到输入框中部再点。
6. 输入区可能已有旧草稿：先 `cmd+a` 全选（用 `computer_aim` 或 `screen_zoom` 确认出现选中高亮），再粘贴；粘贴后必须核对条数与最后一条，避免新旧内容叠加。
7. 粘贴日报（优先）：

```sh
pbcopy < .dsh/tmp/daily-report-$(date +%F).txt
```

然后 `computer_key(key="cmd+v")`。剪贴板被沙箱拒绝或粘贴无效时，退回 `computer_type(element=输入框编号, text=完整日报)`。键盘动作会自动把目标窗口前置；若被拒绝，按第 2 步换窗口，不要硬发。

8. 提交前核对：`computer_aim` 对准右下角「提交」按钮，看局部图里的光标是否压在「提交」上、输入内容是否完整；没压准就按第 4 步换算 `screen_x/screen_y` 重新校准，然后 `computer_click(screen_x=, screen_y=)` **一次**。
9. 提交后可能弹出「AI 工作总结建议」：点「知道了」关闭，然后观察右侧日期是否出现「已提交」、成功提示或表单变化。**弹窗反复出现但没有成功信号时，停下来告诉用户**，不要连续点提交。
10. 页面要求选择日期时，确认为今天；其它必填项保持默认值，缺项时停下来问用户。

**点击失败判定**：点击后界面没有任何变化，或窗口标题跳到了别的标签页，即视为没点中。重新 `computer_aim` 定位后再点，**不要重复点同一坐标**。连续两次点不中就停下来，请用户手动点一下并说明卡在哪里。

## 性能约定

- 采集、写文件、校验都用一次 shell 命令完成，不要分多次往返。
- 不打开终端应用演示命令，不从截图里读 git 输出。
- 观察优先加 `query` 过滤、优先 `ax` 模式；只在需要看画面时才用 `native` 全窗截图。
- 同一界面状态只观察一次；只有界面变化或快照过期才重新观察。
- 拆分条目时用 `--hunks` 的 hunk 头，不读完整 diff。

## 输出示例

```text
1. 新增对外开放接口用于创建招商项目
2. 重构文件路径候选生成逻辑并补充注释
3. 配置项改为按环境变量读取并补默认值
4. 修复会话中企业详情字段缺失
5. 调整账号统计数据范围并补充批注数量
6. 优化研判报告下载链接解析与关联逻辑
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 没有 shell 工具 | 说明当前会话未挂载 shell，让用户重启服务（`./scripts/start.sh restart`）后再跑；不要改用终端 GUI 硬跑 |
| 提交人为空或当日无提交 | 如实说明该仓库当天无记录，不用其它日期凑数 |
| 提交信息过于笼统 | 加 `--hunks` 重跑，按改动点归纳 |
| 合并后不足 6 条 | 按实际条数输出并标注「素材不足」，不编造 |
| 条目超 30 字 | 删修饰词，保留对象与动作 |
| 页面停在登录页 | 停止并请用户手动登录 |
| 匹配到多个同名窗口 | 只操作标注「当前桌面」的那个，并显式传它的 `window_id` |
| 键盘被拒绝（不在当前桌面/无法前置） | 换当前桌面的窗口重新打开页面，不要重试同一动作 |
| 输入框已有旧草稿 | 先 `cmd+a` 全选并确认高亮，再粘贴；粘后核对条数 |
| AX 树为空 | 用 `computer_aim` 校准到目标，看局部图里光标是否压准，再用 `screen_x/screen_y` 点击 |
| 窗口在外接屏、看不到光标 | `computer_aim` 的屏幕图会包含光标；图里是别的桌面说明不在当前 Space，先切桌面 |
| 局部图不含光标 | 宿主未授权「屏幕录制」，回退为窗口缩放图，用返回的坐标误差判断 |
| 点击后无变化 | 视为未命中，重新 `computer_aim` 定位；连续两次失败停下来问用户 |
| 提交后无成功提示 | 再观察一次；仍不确定就告知用户并附全文，不重复提交 |
| 桌面工具不可用 | 仅生成日报并回给用户，不尝试用其它方式绕过 |

## 禁止事项

- 不编造提交、文件、功能或未确认的工作内容。
- 不把未提交改动当作已提交工作，除非用户确认并标注。
- 不在日报里写主观评价、情绪化表达或与提交无关的总结。
- 不用终端应用跑采集命令，不用整窗截图目测坐标点击。
- 不重复点击提交，不绕过登录页，不代填账号密码。
- 不输出 Markdown 列表符号；工作台的输入框只接受纯文本序号。
